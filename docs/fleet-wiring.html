04 · state

What is broken, wrong, or waiting

Verified against the cluster on 4 September 2026, not inferred from the repo.

root cause
A tool can succeed and still tell the agent nothing

get_file_contents returns the file body as an MCP embedded resource. adk-go v2.1.0 — the version kagent 0.10.0-rc1 pins — keeps only TextContent and drops the rest silently, so the model receives {"output":"successfully downloaded text file (SHA: ...)"} and no file. Nothing errors, nothing logs. Two consequences: deploy-diagnostics can search code and read commit metadata but has never read a file, and infra-author — which could also write whole files — overwrote one rather than failing. Fixed upstream in adk-go v2.4.0 / kagent v1.0.0-alpha4 (kagent PR #2541); no 0.10.x release carries it.

stale
incident-commander reports Accepted=False, but works

The message is failed to compile agent: Agent "deploy-diagnostics" not found — recorded at observedGeneration 4 on 16 Aug, when that agent genuinely did not exist yet. It exists now. The condition was never re-evaluated, so kagent's own console refuses the chat while the pod answers A2A requests normally. A controller restart clears it.

wrong
deploy-diagnostics declares a tool that does not exist

get_repository_tree is not in the running github-mcp-server image. It resolves to nothing, so the agent browses directories with get_file_contents and a trailing slash instead. Harmless, but it is dead weight in the allow-list.

risk
kagent-tools holds literal cluster-admin

A chart default, not a choice. Every per-agent allow-list above is enforced at the agent, not at the tool server — so the tiering describes what agents are offered, while the server behind them could do anything. The allow-lists are the control today; the ServiceAccount binding is the thing that would need narrowing to make that structural.

by design
Three kagent built-ins carry broad mutating tools

k8s-agent, helm-agent and istio-agent between them can create, delete, patch, exec, install Istio and uninstall Helm releases. Nothing in ARIA routes to them and they are not exposed through the Operations tab — but they are reachable by anyone with console access, which is worth stating out loud rather than leaving implied.
