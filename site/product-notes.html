ARIA Agentic Runtime for Infrastructure Automation

kagent ships powerful, individually-expert Kubernetes agents. None of them are governed — no read/write boundary worth trusting, no cross-domain synthesis, no way to know if an answer is actually grounded. ARIA is the layer that makes them safe to hand to an engineer.

status: solo PoC platform: kagent + EKS stage: diagnosis + orchestration proven
The gap

What raw kagent gives you vs. what ARIA adds

This isn't a rebuild of kagent's specialist agents — it's the governance and orchestration layer sitting on top of them, reusing the ones that are already safe to use directly.

kagent, used directly

  • Every specialist is single-domain — cross-domain root cause is manual chat-hopping
  • k8s-agent ships with patch / delete / create / exec, live, no approval
  • No verification layer — nothing checks if an answer is actually grounded
  • Config-level tool scoping only — no RBAC backstop underneath it

Through ARIA

  • One orchestrator synthesizes findings across specialists into one root-cause narrative
  • Read-only-by-design diagnostic agent, mutating tools stripped entirely
  • Every agent answer graded against its own tool-call evidence, CI-gated
  • Mutating actions (planned) route through an explicit human-approval gate

The shared tool server backing every agent — including the read-only ones — runs with literal cluster-admin by default. The "read-only" guarantee today is config-level only. Fixable natively via the chart's own rbac.readOnly flag; not fixed yet — accepted trade-off for a solo PoC, not production.

Requirements, roughly

If this were framed as user stories

On-call engineer

"I want one place to ask why something's broken and get a synthesized answer with evidence — not four chat tabs I have to cross-reference myself."

Platform lead

"I want every diagnostic agent read-only by default, so giving engineers self-service access doesn't also mean giving them blast radius."

Approver

"I want to see exactly what an agent wants to change and why, with one click to approve or reject, before anything touches the cluster."

Platform owner

"I want a CI gate that fails when an agent's answers stop being grounded in real evidence — the same way a test suite fails on a real regression."
