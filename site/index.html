The open stack

Every layer is open source. The one paid dependency is swappable.

A platform you can't take apart is a platform you don't own. ARIA's entire operating stack is open and CNCF-aligned — the only proprietary piece, the model itself, sits behind an open API so it swaps for a self-hosted one without touching anything else.

Why it's built this way

Four commitments, each a deliberate reaction to how these platforms usually go wrong.

01

Own every layer

The whole operating stack is open source and self-hostable. The usual path — bolting together a dozen paid SaaS products — buys speed and sells your ability to ever fully own or audit the thing.

02

Governed by construction

Two enforcement points, not a policy PDF: Kyverno at admission (an agent can't deploy without limits, scoped RBAC, and tracing) and an eval gate at runtime (answers checked against real evidence, in CI).

03

Reproducible, not clicked

Every agent, policy, and piece of infra is git-declared and ArgoCD-synced. There is no console-clicking path to production — the cluster is whatever the repo says it is.

04

Focused, not sprawling

One band of the stack — deploy and operate — covered end to end. Not eighteen half-finished domains on a roadmap slide.

The trust loop

An LLM answers with a 200 OK whether it's right or wrong. So we check.

Every agent answer is graded not on whether it sounds right, but on whether its claims trace back to the tool calls it actually made — a groundedness gate, wired into CI. It isn't theoretical. On its first real run it caught a genuine bug:

Caught in eval · fixed · verified

A "read-only" agent confusing its own name for a namespace

The diagnostics agent reported a connectivity check as failed — and its answer matched what the tool returned, so a text-only check would have passed it. But the grounded check saw how it called the tool:

# what the agent actually invoked k8s_check_service_connectivity({"namespace":"cluster-diagnostics", ...}) # ↑ that namespace doesn't exist — it passed its own agent name. # the "failure" was a false negative, reported with full confidence. → root cause: its prompt never told it which namespace it runs in. → one-line fix, re-run, confirmed green.

Where trust meets delivery

Eval-gated progressive delivery

The trust loop and the deployment pipeline are the same loop. A new agent version canary-deploys to a slice of real traffic; its groundedness scores are measured live; it promotes itself only if it holds the bar, and rolls back if it doesn't — no human watching a dashboard at 3am to make the call.
